# Problem brief authoring and time measurement

Create 3–5 briefs only from named buyer conversations. The three records in the alpha are demonstrations and do not count.

## Timer protocol

Use one row per work session. `Active hours` excludes waiting for replies; `elapsed days` runs from first interview to buyer acceptance. This separates authoring cost from organisational latency.

| Brief ID | Session date | Activity | Active minutes | Waiting on | Evidence produced |
| --- | --- | --- | ---: | --- | --- |
|  |  | Interview / research / drafting / review / revision |  |  |  |

Summary per brief: active authoring hours `___`; buyer review hours `___`; elapsed days `___`; revision rounds `___`; author `___`; buyer acceptance timestamp `___`.

## Required brief

- **Problem:** observable operating failure, independent of a proposed solution.
- **Baseline:** current value, sample, time window and evidence source.
- **Target:** metric, threshold, evaluation method and disqualifiers.
- **Value:** cost of the problem and how calculated; label estimates.
- **Decision owner:** named role with acceptance and budget authority.
- **Budget and route:** amount, funding source, procurement/contract route and timing.
- **Environment:** physical/digital constraints and safety requirements.
- **Sponsor inputs:** data, equipment, people, site time and approvals with due dates.
- **IP/data posture:** background IP, requested rights, confidentiality and data constraints.
- **Out of scope:** explicit non-goals.
- **Failure value:** what a negative validation result would decide.
- **Acceptance:** version and timestamp from the decision owner.

## Quality gate

A brief is `real` only when the decision owner confirms the baseline, criterion, sponsor inputs, budget range and approval route. It is `fundable` only when a smallest next step has a quote, duration, frozen criterion and useful failure meaning.
